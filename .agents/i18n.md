# Translations

Runtime lookup lives in `src/lib/state/i18n.svelte.ts`. Strings are flat `Record<string, string>` JSON under `static/data/lang/`, fetched per route and merged route -> lib -> commons, first hit wins. `static/data/lang/index.json` is generated by the `electris-lang-index` plugin in `vite.config.ts`; never edit it.

## Plain strings: `t()`

`t(key, fallback?, locale?)` returns a string. Use it for everything that is not rendered as body text: attributes (`title`, `aria-label`, `alt`, `placeholder`), component props, and plain interpolation.

## Rich strings: `<T>`

A translation may carry markup. It is never passed to `{@html}`; `parseRichText` in `src/lib/utils/i18n.ts` turns it into a node tree and `src/lib/components/ui/T.svelte` renders that tree as real elements.

```svelte
<p class="statement"><T key="about.elts.statement" /></p>
```

`<T>` takes the same `key`, `fallback` and `locale` as `t()`.

### What counts as markup

Whitelisted tags render as themselves:

```
br strong b em i u s small code mark sub sup span
```

Anything else is literal text. `<script>`, `<img>`, `<a href="...">` and prose like `a < b` all render as the characters they are, so a translation file cannot inject an element or an attribute. That is the security boundary: the whitelist is what the renderer can build, not a list of things to strip.

Unclosed tags auto-close at the end of the string; a closer with no opener renders literally.

### Slots

`<0>` through `<9>` are filled by the page, for anything needing an href, a class, or a component. Pass a matching `s0`-`s9` snippet, which receives the wrapped content as a snippet:

```json
"legal.tos": "Read the <0>terms of service</0> first."
```

```svelte
<T key="legal.tos">
  {#snippet s0(text)}<a href="/terms">{@render text()}</a>{/snippet}
</T>
```

Use a slot rather than putting a URL in the translation file: the URL then lives in one place instead of once per locale. A slot with no snippet renders its content unwrapped.

Slot indices are a single digit on purpose, so prose like `<10>` is not mistaken for a tag.

## Dev warnings

Both are browser-only and fire once per key.

- `t()` returning a string that contains markup means the call site would print the tags verbatim. Switch it to `<T>`, or to a plain string if the site is an attribute.
- A slot in the string with no matching snippet prop.

## Adding markup to a string

Both halves have to move together. Adding `<strong>` to a key still rendered through `t()` prints the literal tag, so convert the call site to `<T>` in the same change. Keep the tags consistent across every locale file for that key.
